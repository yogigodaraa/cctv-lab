Evaluation on long footage

Two views. Video level: a clip counts as flagged if any 2 s segment reaches the threshold. Operator level: consecutive flagged segments merge into one alert; false alarms per hour are counted on normal footage only, and a ground-truth fight counts as caught if any alert overlaps it.

X-CLIP and SmolVLM are zero-shot; xclip-probe is trained and scored with 5-fold cross-validation grouped by video. Footage: UBI-Fights (Degardin & Proença, 2020), frame-level annotated, research use only.

How a clip becomes an alert

  1. VideoExisting CCTV footage, any length
  2. 2 s windowsCut into back-to-back 2-second segments; a few frames are sampled from each
  3. ModelEach segment gets a fight score from 0 to 1
  4. ThresholdSegments at or above the threshold are "hot"
  5. AlertConsecutive hot segments merge into one alert for a human operator

Frames are analysed in memory on the local machine and never stored; only scores and short captions are saved. No face recognition, no identification.

Models in use

Planned next

Pose-based classifierplanned

Extract body keypoints (skeletons) per person, then classify their movement over time with a graph network (e.g. ST-GCN). Sees motion and interaction, not appearance, so it is privacy-preserving by design. This is the core of the research.

Fine-tuned video modelplanned

Fully fine-tune a video transformer (e.g. VideoMAE) on fight data instead of only training a head. Usually the strongest RGB baseline, but heavier to run and looks at raw pixels.

Larger VLM as a second opinionplanned

A 2–7B vision-language model (e.g. Qwen2.5-VL) that only looks at clips a fast model already flagged, to explain or veto them. Aims to cut false alarms without running the slow model on every feed.

Research questions

Measure what privacy costs in fight detection, and cut false alarms on look-alike activities, on hardware a CCTV site already has.

Kaggle GPU worker

Open notebook on Kaggle
  1. Queue work here: upload clips, press a model's Run button, or "Queue unscored" below.
  2. Start the notebook: on Kaggle press Run All (or Save Version → Save & Run All to run in the background). First time only: Add-ons → Secrets → add WORKER_TOKEN and switch it on; Settings → Accelerator GPU, Internet On.
  3. Watch it here: a worker named kaggle-… appears above as online, jobs move from queued to done below, and scores show up on every tab as each job finishes. Nothing to download.
  4. It stops itself after 20 minutes with no new job (or 11.5 h), so the free GPU quota (~30 h/week) is only spent on real work.

Scheduling: kaggle kernels push starts a new background run, so a timer (cron on any machine, or a scheduled GitHub Action with a Kaggle API token) can re-run it, e.g. nightly; each run drains the queue and stops. Keep the notebook private: it downloads research-only footage.
